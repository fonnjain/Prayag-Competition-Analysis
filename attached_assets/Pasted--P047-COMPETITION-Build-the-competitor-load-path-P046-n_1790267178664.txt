# PART 2 — Replace the byte-hash gate with a content fingerprint

An `.xlsx` is a zip. Re-saving changes every byte while the values stay identical. **A byte-hash gate has already blocked a legitimate load once, under P027.**

**2.1** Gate on a content fingerprint: normalised parsed business rows, sorted, joined by LF with no trailing LF, UTF-8, SHA-256. That is the definition you computed — keep it, and write it down where the next person will find it.

**2.2** **Enumerate worksheets from the file, never from a brief.** The Apollo file has 13 sheets and one is named `" CPVC PIPE"` with a leading space. A brief-driven list would miss or mangle it, which is how P027r2 read 11 sheets of 13 and lost 137 prices.

**2.3** Store the content fingerprint on every batch from now on, so a future load has something to compare against. Report that the Apollo development batch's fingerprint is `6b6c87af32eea3ff21d5f4fadd2af892e3d777ec182c998f54416216d1043181`, or recompute and report what you get.

**2.4** The byte hash stays recorded as metadata. It just stops being the gate.

# PART 4 — Every competitor price row carries its batch id

**4.1** Each row written by a load carries the id of the batch that wrote it. No nullable path, no exception — same rule P039 established for MRP prices, now in the competitor table.

**4.2** Report every write path that reaches the competitor price table and confirm each attaches a batch.

**4.3** **Do not add `NOT NULL` yet.** If Part 1 found existing rows without a batch id, the constraint cannot be added until those are resolved — and that is a separate decision. Report whether the constraint could be added today, and if not, what stands in the way.

That sequencing is the lesson from P039: **the data first, the constraint second.** A constraint added over unresolved rows either fails or gets forced.

# PART 5 — One-action undo

**5.1** An applied competitor batch can be undone in one action, restoring the exact prior state.

**5.2** The undo stores what it needs to restore — a snapshot of the affected rows, in the batch record.

**5.3** Report the window it stays open for.

**5.4** If a constraint or a later batch would make an undo unsafe, it **refuses cleanly with an explicit error** rather than partially applying. That was the ruling on P039's undo and it holds here.
