## Step 4 — Effective date on competitor import

Add a required **"Effective Date"** date-picker to the Import Competitor form.
- Store `effectiveDate` on every imported row.
- Re-uploading the **same competitor for the same effectiveDate** replaces that period's rows; a **new effectiveDate adds a new period** (older periods kept); newest per (competitor, product) becomes `isCurrent = true`.
- Keep the existing auto-match guardrail (reject gaps outside ~−80%..+100%) for auto-matched imports; verified manual re-uploads bypass it.

## Step 5 — Effective-date filter in the analysis dashboard

In `prayag-analysis` + `analysis.ts`, add a period filter (dropdown):
- Options = distinct effective dates across `mrp_price_history` + `competitor_prices`. Default = latest.
- For the chosen date, per product:
  - **Prayag MRP** = the `mrp_price_history` row with the latest `effectiveDate <= chosen`.
  - **Competitor price** = the `competitor_prices` row (that competitor + product) with the latest `effectiveDate <= chosen`.
  - Recompute diff% live using the existing rule (competitor ex-GST × 1.18 vs Prayag MRP; positive = Prayag cheaper).
- Changing the filter recomputes coverage/positioning/opportunity KPIs for that period.

## Step 6 — Period-to-period MRP increase (Prayag + competitor)

For each item, order its prices by `effectiveDate` and compute:

```
increase% = (this_period_mrp − previous_period_mrp) / previous_period_mrp × 100
```

Show per product (a Price History panel / expandable row) the MRP by period and the % change between consecutive periods — for **Prayag** (`mrp_price_history`) and for the **competitor** (`competitor_prices` history) — plus an overall "biggest MRP increases this period" view.

*(Optional data:)* if `0_Prayag_Master_MultiPeriod.xlsx` is uploaded, append its `mrp_price_history` sheet so Prayag has full price history from day one. Append only (match on `item_code` + `effective_date`; skip rows that already exist) — do not modify existing rows.

That sheet has a `status` column with three values:
- `Previous` — an older period, `is_current = false`.
- `Current` — the price effective **today**, `is_current = true`.
- `Upcoming` — a **future-dated** price (e.g. PTMT w.e.f. 01 Sep 2026) that is not yet in force. Load these rows with `is_current = false` and **exclude them from the default comparison**, so today's numbers never use a future price. They should still appear in the price-history panel and be selectable in the period filter.
