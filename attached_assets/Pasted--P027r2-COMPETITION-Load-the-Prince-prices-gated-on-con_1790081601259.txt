## 1. Why the hash did not match

A `.xlsx` is a zip. Opening it and saving it — in Excel, in Google Sheets, on the way through Drive — rewrites that zip with new timestamps and a different compression order. **Every byte changes while every value stays the same.** A byte hash therefore proves the file was never re-saved; it does not prove the data is the same, and it fails constantly on files that travel through a spreadsheet application.

So do not authorise the received hash and carry on. Verify the **content** instead, which is what the gate was trying to protect in the first place.

Record both hashes in `mrp_load_batches`: the byte hash of the file you actually received, and the content fingerprint below. The byte hash still has a job — proving *which* file you read — it is just not the thing that decides whether to proceed.

## 2. The content gate

Read the workbook. Before writing anything, compute this fingerprint and compare.

**How to build it.** For every row that has both a Prince item code and a Prince price:

```
line = NORM(prayag_code) + "|" + NORM(prince_code) + "|" + price_to_2dp

NORM(s)  = uppercase s, then remove every character that is not A-Z or 0-9
price    = formatted to exactly two decimal places, e.g. "536.25", "273.00"
```

Sort the lines as plain ASCII strings, ascending. Join with a single `\n` — no trailing newline. Encode UTF-8. SHA-256.

```
rows with a Prince code and price     813
sum of all Prince prices              1049375.55
CONTENT FINGERPRINT
  901d63a62e8eb4ea9de728e1cec2b3d4c1a1ef23d871a0b3246fa8e090658a17
```

**If the fingerprint matches, proceed.** The data is identical to what was analysed, whatever the file bytes say.

**If it does not match, stop again** — but this time report the three diagnostics below so the difference can be identified, rather than only the hash:

```
your row count            (expected 813)
your price sum            (expected 1049375.55)
your per-worksheet counts (expected, below)
```

## 7. Make this the standard

This is P006's subject — the authoritative load hash contract, written and never issued. The lesson is now paid for, so build it in rather than repeating this exchange on the next file:

**Every workbook load gates on a content fingerprint and records the byte hash alongside it.** The byte hash identifies the file. The fingerprint decides whether to proceed. A spreadsheet that has been opened and saved is the normal case, not an anomaly, and a contract that fails on it will simply be switched off by whoever is in a hurry.
