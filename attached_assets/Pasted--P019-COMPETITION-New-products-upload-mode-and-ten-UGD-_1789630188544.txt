## 3. A new-products upload mode

Today the options are the **MRP revision upload**, which by design cannot create a product, and the **Load MRP** form, built for a full authoritative catalogue. Neither fits ten new products, and the loader is far too heavy an instrument for it.

Add a third mode. Small, explicit, and narrower than both.

### It is for Prayag products only

**The mode must not be available on competitor uploads.** A competitor file has never been allowed to create a Prayag product, and that rule is load-bearing — it is what stops a Sparsh or Prince catalogue inventing entries in our own. Do not offer the option there at all; an option that must never be chosen is still a way to choose it.

### What it accepts

```
item_code · division · series · product_name · size · mrp · effective_date
```

Same shape as the authoritative master's `products` sheet, so a slice of that file works without reformatting.

### Creating a product is not the same as changing a price

The preview must separate the two plainly:

```
Will CREATE 10 products
  U-11CS   UGD Self Fit Pipe (6 Mtr) SN-8   Rs 2,987   from 10 Aug 2026
  U-12CS   ...

Rejected 2 rows
  PU-3311  already exists in the catalogue.
           Use the price revision upload to change its price.
```

**An existing code is a rejection, not an update.** If a row names a code already in the catalogue, that is not a new product — reject it and say which tool handles it. Silently updating an existing product from a file labelled "new products" is how a price changes without anyone deciding it should.

### Periods

A row may name an **existing** period, as these ten do with `2026-08-10`, or a genuinely new one. Both are legitimate for a loader — but state clearly which is happening:

```
2026-08-10   existing period, currently 580 rows   ->   590
```

If the date has already passed, say so and give the count going live immediately.

### After it commits, report the competitor effect

Adding a Prayag product can resolve competitor rows that were waiting for it — as these ten do for Prince. The upload should report that without being asked:

```
7 competitor rows moved from Needs Review to Ready
  Prince: SIM200965, SIM200960, SIM200961, SIM200962,
          SIM200963, SIM200955, SIM200956
```

That is the connection someone would otherwise have to go and look for.

### Provenance

A load batch as usual — file name, SHA-256, upload date, reason, and the mode used. A batch that created products should be distinguishable from one that loaded prices.
