## Step 6 — smoke-check the two pages that depend on this

This is the reason the apply happens before the calculator goes in front of users. Read-only, on
production:

1. **Price Finder** — division dropdown lists exactly the seven, `Sink` among them, no composite
   strings, scroll and search both work (P057 Part B).
2. **Calculator** — pick `Sink` → a category → a product; it resolves. Then pick one of the former
   composites (`501N`, `503N`, `701N`) and confirm it now appears under a single division.
3. **Competitor scoping** (P057 Part C) — with a division and category chosen, only competitors
   holding prices for that scope are offered.
4. Confirm the unit badges still behave: neutral note where the competitor unit is unrecorded, amber
   only where both units are recorded and disagree.

Nothing here should need a code change. If one of them is wrong, it is a scoping bug exposed by real
division data, not a data problem — report it separately and do not touch the division table again.
