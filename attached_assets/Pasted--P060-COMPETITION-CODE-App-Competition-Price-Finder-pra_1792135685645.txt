## 0. Read this first

### 0.1 This prompt SUPERSEDES P059. Do not run P059.

P059 proposed a `product_divisions` membership table on the theory that the 57 pipe-joined products
genuinely sell into several divisions. **That theory was wrong.** The `source_sheets` column in
`Prayag_Allowed_Codes_Master` shows the composite string is just *which workbook sheets the code was
found on* — provenance that leaked into the division field, not commercial membership.

So: **no membership table, no browse/filter query rewrites.** Each product gets exactly one division,
taken from the attached mapping file. That is a far smaller and safer change.

### 0.2 Amendment to P057 Part A.3(a) — the item-code backfill must NOT run

Keep the `normCode` consolidation and the `matchKey` rename. **Do not** re-point `authoritativeCode`
at the canonical `normCode`, and **do not** change what any loader stores.

Reason: the catalogue contains pairs that differ only by internal whitespace and are **genuinely
different products**:

| Code | Product | Division |
|---|---|---|
| `TTS-01` | TEFELON TAPE | CP Fittings / Faucets |
| `TTS - 01` | Teflon Thread Seal (10 mtr. L) 12mm | PTMT & Plastic Fittings |
| `DB-02L` | Ball **Long** Cock+Ball (ISI) | Ceramic Sanitaryware |
| `DB-02 L` | Ball Cock+Ball (ISI) | PTMT & Plastic Fittings |

Canonical normalisation would merge them. **Whitespace is significant in this catalogue's item codes.**
`normCode` is for comparison and fuzzy lookup only, never as an equality test between two stored codes.

### 0.3 The source rate list's prices are NOT to be used, anywhere, for anything

The mapping file was derived from `rate_list.xlsx`, an ERP export. **That file has no effective-date
column at all**, and its MRP disagrees with the authoritative workbooks:

| Code | ERP rate list | Authoritative |
|---|---|---|
| `321` | ₹62 | ₹92 w.e.f. 01-09-2026 |
| `U21` | ₹84 | ₹78 |

Nothing in this prompt touches `mrp_price_history`, `competitor_prices`, or any price field. If you
find yourself writing a price, you have gone off-script — stop.

## Part A — Sink becomes a seventh division

Business instruction, 16 October 2026. The app currently has six divisions; it will have seven.

**Definition (already applied in the mapping file):** Sink = ERP Master Group `SINK`, which is exactly
Item Type ∈ {`SINK`, `FLOOR TRAP`, `PLATE RACK`} — **656 codes**. Floor traps and plate racks are
included deliberately; the ERP files all of them under Master Group SINK.

All 656 currently sit under **PTMT & Plastic Fittings**, which drops accordingly.

### A.1 Code changes

1. **`artifacts/api-server/src/lib/mrpProvenance.ts`** — `OFFICIAL_MRP_SOURCES` (~L37-76) is a
   six-division list used as the canonical division vocabulary **and** as the MRP workbook list.
   Those are now two different things. Split them:
   - `PRODUCT_DIVISIONS` — the seven product divisions, exported as the single source of truth.
   - `OFFICIAL_MRP_SOURCES` — unchanged, still the six MRP workbooks.
   - **There is no Sink MRP workbook.** Sink items price from the PTMT book, so for them
     `productDivision` ≠ `sourceDivision`. `mrpProvenance.ts` already distinguishes these two
     concepts — make sure the Sink case flows through that distinction rather than breaking it.
     Add a code comment saying why, so nobody "fixes" it later.
2. **`artifacts/api-server/src/routes/catalogImportExport.ts`** — derive `FILENAME_DIVISION_MAP`
   (~L817-831) from `OFFICIAL_MRP_SOURCES`, not its own literals, and add the missing `/hardware/i`
   pattern (per P057 A.3f). Do **not** add a Sink filename pattern — there is no Sink workbook.
3. **`catalogImportExport.ts:707`** — the `anomalyReasons` regex is a fourth spelling set. Point it at
   the shared constant too.
4. **UI** — the division appears in Price Finder browse, Product DB catalog, and the Analysis
   dashboard. All three read divisions from the API, so no hardcoded list should need editing.
   **Verify that** — grep the front-ends for any literal division array and report what you find.
