**Enforcement works correctly — do not change how it works.** The Move control is correct as built — do not redesign it. Four small changes.

---

# 1. Visibility defaults by role

On the create page, **Visibility** keeps both options for everyone. Only the default changes:

```
Admin creating a list       ->  Everyone (Head Office list)
Non-admin creating a list   ->  Only me
```

**1.1** An admin almost always makes a company list; a user almost always makes a personal one. Default to the common case and leave the other one click away.

**1.2** This is a default only. Either role can change it before saving.

**1.3** When **editing** an existing list, the control shows that list's current visibility. No default applies.

---

# 2. What a non-admin can do

**2.1 Make lists.** Either visibility, as many as they like, with products, competitors or both. Edit, rename and delete their own.

**2.2 Use any list they can see as a filter** — their own and every HO list.

**2.3 They cannot enforce or un-enforce anything.** No control on screen, and the endpoint returns 403.

**2.4 They cannot move any list**, including their own. No control, 403 on the endpoint.

**2.5 They cannot see, edit or delete another user's private list.**

---

# 3. What an admin can reach

**3.1 An admin can see every list** — HO lists and every user's private list. This is a change: today a private list is hidden from admins too.

It follows from §3.2. An admin cannot enforce a list they cannot see, and cannot answer "why is this product missing from my report" if the list doing it is invisible to them.

**3.2 An admin can enforce any list** — an HO list, or any user's list, their own included. One list in force at a time, company-wide, exactly as it works now.

**3.3 Enforcing a private list publishes it to HO in the same action.** It has to: every export names the list in force, and 181 people cannot be filtered by something only one of them can open. Say so in the line afterwards, do not ask:

> *"CP review" is in force, and is now an HO list so everyone can see what is being applied.*

**3.4 A user's private list shows its owner's name** wherever an admin sees it, so it is clear whose it is.

**3.5** Moving a user's list to HO lists stays **admin only**.

**3.6** Through any move or enforcement the list keeps its **id, items, competitor rules and history**. Never a copy. **The creator keeps the right to edit it**, and so does any admin.

---

# 4. "Last changed" is showing a reason instead of a person

Not a design change — a defect. On production now:

```
No Ashirwad                  CEO Prayag                      10/10/2026, 2:17:05 PM
HO (Plumbing) — Excluded     Approved list-name correction   10/10/2026, 4:07:57 PM
```

The second is not a person. The rename wrote its own description into the actor field.

**4.1** That column answers **who changed this and when**. It holds the acting user — nothing else, ever.

**4.2** Correct the row the rename wrote: the change was made by the signed-in admin.

**4.3** Check every other path that writes this field — create, edit, rename, upload, move, enforce — and make sure each stores the acting user, not a description of the action.
