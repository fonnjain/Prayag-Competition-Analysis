# P049 — Step 2 — COMPETITION — Series becomes Range, for CP, Sink and PTMT only

> **P049 Step 2** · app: **COMPETITION** (`prayag-price.com`)
> **THIS PROMPT CHANGES CODE.** It changes screens and one loader. **It changes no stored product value.**
> Quote `P049 Step 2` when reporting back.

Prayag has ruled on P049:

> **Series applies only to CP, Sink and PTMT, and is renamed Range. It is not the same thing as Category.**
> **Sink is a Division.**

So the field is real but has the wrong name and the wrong reach, and one loader is filling Category with it. This prompt implements the ruling and **moves no data**.

# PART 1 — Rename the label, not the column

**1.1** Everywhere the **user sees** "Series" (editor, Create New Product, filters, tables, exports, column headers), it becomes **Range**.

**1.2** **Do not rename the database column `series_range`**, and do not change any field name in what syncs to the Sales application. Sales reads `series_range` into `mrp_synced.series_range` and `mrp_master.series`. Renaming the column breaks that sync silently.

**1.3** List every place you changed the label, so nothing is left saying Series.

---

# PART 2 — Range is shown only for CP, Sink and PTMT

**2.1** In Create New Product and the Single Product Editor, the **Range** field and its **Add** button appear **only** when the chosen division is one of the Part 0 set.

**2.2** For those divisions, decide from the data whether Range should be mandatory. Report how many CP/Sink/PTMT products have **no** range today. If many do, make it optional and say so. **Do not invent ranges to fill the gap.**

**2.3** For every other division, Range is **hidden and not required**. Today it is marked mandatory (*) for every product, which forces a value onto a pipe or a fitting.

**2.4** **A hidden field must not be cleared on save.** Editing a pipe product that already holds a `series_range` value leaves that value exactly as it was. Test this explicitly.

**2.5** The set of Range divisions is held in **one place**, easy to change, not repeated across screens. When Sink's division is settled, adding it is a one-line change.

**2.6** The Add Range button keeps everything P048 Step 2 built: admin only, normalised comparison, stored as typed, typed reason, actor and timestamp, empty on creation. Only its visibility and label change.

# PART 3 — Stop the master loader copying Range into Category

P049 found that the authoritative master loader writes its series value into **both** `series_range` **and** `category`.

**3.1** Change the loader so `series_range` is written **only** for CP, Sink and PTMT rows, and `category` is **never** written from the series/range column.

**3.2** Report what the loader will now write into `category` instead, and from which source column. **If the master has no real category column for some sheets, say so.** Do not fall back to copying range into category, and do not leave category NULL. That recreates Uncategorized (P029, P035, P036). **Refuse the row with a clear message** instead, and report how many rows in the current master would be refused.

**3.3** The generic importer already maps `GROUP` to category and `RANGE` to series. Confirm it is unchanged, and that `RANGE` is only accepted for the Part 0 divisions. Report, don't refuse, if other divisions supply it today.
