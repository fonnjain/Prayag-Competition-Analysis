# PART A — Exclude a competitor

A bucket list can now hold competitors as well as products.

**A1. A third tab in the editor, "Competitors".** Lists the four stored competitors — Apollo, Ashirvad, Prince, Sparsh Pearl — read from the database, never typed. Each has a checkbox and a scope:

```
Apollo         Everywhere
Prince         By division ▾     Pipes & Fittings
Ashirvad       By category ▾     SWR Fittings, Pipe Clip
```

Division and category pickers offer only values where that competitor has prices, with counts. Category matching uses the existing P051 normaliser. A competitor may have more than one rule; they add up.

**A2. Excluding a competitor does not remove Prayag products.** It removes that competitor's prices from the comparison. The product row behaves exactly as it does today for a product with no competitor.

**A3. The one thing that must be right: an excluded competitor leaves every total.** Widest gap, positioning, coverage, by-brand, by-category, opportunities, rival counts, medians. Filter at the source of each aggregate, not on the rendered rows. A total that still counts a competitor the user excluded is a wrong number, and that is the only reason this feature exists.

**A4. Show what was lost, as one line**, on screen and in the export, computed and hidden when zero:

```
67 products have no competitor price under this filter
```

Reference counts if every competitor were excluded in turn: Apollo 67, Ashirvad 84, Prince 217, Sparsh Pearl 150.

**A5. Included lists**: a competitor rule means "show only these competitors". A list naming no competitor says nothing about competitors — all are shown.

# PART B — HO Enforced

**B1. A fourth tab on the Bucket Lists page: "HO Enforced".**

- Nothing in force: says so. Admins get **Enforce a list**, picking from HO lists only.
- Something in force: name, type, effect, who, when. Admins get **Take out of force**.
- Non-admins see the tab read-only, so they can tell what is being applied to them.
- Below, a plain list of the last changes: action, list, who, when. No reason field.

**B2. One enforced list at a time, company-wide.** Enforcing another replaces it. Admin only; the endpoint returns 403 for everyone else.

**B3. How it combines.** The enforced list always applies and a user cannot clear it. A user may apply one of their own lists as well, and both take effect. **Exclusions win**: an Included personal list can only pick from what survived the enforced list.

```
catalogue -> enforced list -> the user's own list -> what they see
```

**B4. Admins are subject to it too.** To see everything, take it out of force.

**B5. A list in force cannot be deleted.** Refuse, saying to take it out of force first. Editing one in force is allowed and takes effect immediately; no confirmation dialog.
