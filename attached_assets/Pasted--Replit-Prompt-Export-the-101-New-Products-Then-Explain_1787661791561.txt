## Part B — Why did two runs differ by 15?

Same PDF, same catalogue profile, two batches: one found 86 new products, the other 101. The mapped 150 were identical in both.

That is not a rounding difference. Report:

1. **Which batch ran first**, with timestamps.
2. **What changed between them** — extractor code, catalogue profile, prompt, model, page list, DPI. If nothing changed, say so plainly.
3. If nothing changed, then **the extractor is not repeatable on the same input.** State that as the finding.

The three codes batch `#13` found and the independent read missed — `RPS-2276`, `RPS-2284`, `RPS-2290` — are all page 27 Stop Cocks, which sit in the small two-code tiles the runbook flags as error-prone. That is consistent with the variance being concentrated in a specific tile layout rather than spread randomly.

**This matters beyond this catalogue.** If two runs of the same extractor on the same PDF can differ by 15 products, then a single run is not sufficient evidence of coverage, and every future competitor catalogue has the same exposure. The two-pass read with adjudication that was specified for price extraction addresses exactly this — report whether it was ever implemented, and whether it covers code discovery as well as prices.
