# P030 — COMPETITION — Verify what P029 classified, and correct the joint type if it was copied

> **P030** · app: **COMPETITION** (`prayag-price.com`)
> **Read-only in Part 1. Changes data in Part 2 only if Part 1 finds a problem.**
> Quote `P030` when reporting back.
> **Run this after P029 completes.** It supersedes P029r2, which was never issued.

P029 told you to copy each Self Fit product's classification from its Ring Fit sibling. That instruction has a gap in it, and this prompt closes it.

## The gap

`U-11CS` is **Self Fit**. `U-11C` is **Ring Fit**. They are different products.

They are identical in size, SN rating, price, division and series — which is why copying works for those fields. But **if any field in the schema encodes the joint type, copying the sibling filed every Self Fit pipe as Ring Fit.** Uncategorized would have cleared, every P029 test would have passed, and the catalogue would be wrong in a way that surfaces when a distributor is shipped the wrong pipe.

P029 could not have caught this. Its tests check that the copy succeeded, not that it was correct.

Report, for a catalogue product:

3. The values currently held by **`U-11CS`** and **`U-11BS`** (Self Fit) for the same fields.

Rows 2 and 3 side by side answer the question on their own.

## 1.2 The verdict

State plainly which of these is true:

**(a) No field encodes joint type, fit type or connection type.**
P029's copy was correct and nothing needs changing. Part 2 does not run.

**(b) A field encodes it, and P029 copied the Ring Fit value onto all ten Self Fit products.**
Ten products are mislabelled. Part 2 runs.

**(c) A field encodes it and P029 did not copy it** — left empty, or set correctly.
Report what it holds. Part 2 runs only if the field is empty.

Name the field. Quote its permitted values. Do not paraphrase.

# PART 2 — Only if Part 1 returns (b), or (c) with the field empty

## 2.1 What to set

These ten products are Self Fit. The evidence:

- The competitor master groups them under the section heading **`SELF FIT (SN-8)`** and **`SELF FIT (SN-4)`**, directly beneath `RING FIT (SN-8)` and `RING FIT (SN-4)`.
- Every code ends in `S`.
- Each mirrors a Ring Fit sibling at the same size, SN rating and price.

```
U-11CS U-12CS U-13CS U-14CS U-15CS U-16CS     SELF FIT, SN-8
U-11BS U-12BS U-13BS U-14BS                   SELF FIT, SN-4
```

**If the field's permitted values contain an unambiguous Self Fit option**, set it on all ten.

**If they do not** — the field is free text, or the options are unclear, or nothing corresponds to Self Fit — **clear the field on all ten** rather than leaving a wrong value, report it, and stop. The correct value then comes from Prayag.

A field that is empty is visibly incomplete. A field that says Ring Fit on a Self Fit pipe is invisibly wrong, and worse.

## 2.2 What must not change

1. **No price written.** `mrp_price_history` count and checksum identical before and after.
2. **No name changed.**
3. **No competitor mapping changed.** Snapshot `competitor_prices` and Needs Review before and after; the diff must be empty. Those seven Prince prices stay.
4. **Division, series and every other field P029 set stay as they are.** This prompt touches one field.
5. **No product created, none deactivated.** Codes 20, 25, 32 untouched.
6. Preview, then Apply. Admin only. Provenance and one-action undo.
7. Development first, then publish, then the same flow in production.

## 2.3 Do not undo P029

Undoing P029 wholesale would return all ten products to Uncategorized, which is worse than a wrong joint type — they would again be invisible to category navigation, with live Prince comparisons attached. Correct the one field in place.
