## 4. If it fails

**Report the exact error text, verbatim, and stop.**

Do not resolve it by rebasing, squashing, amending, force-pushing, cherry-picking, creating a new branch, creating a new repository, or switching to a different remote. Every one of those hides the cause and some of them lose commits.

The likely causes, in order, so you can say which one it is:

| Symptom | Cause |
|---|---|
| `403`, `invalid credentials`, `authentication failed` | the GitHub token has expired — the human must reissue it |
| `rejected — non-fast-forward` | GitHub has commits this workspace does not; report what they are, do not merge |
| `remote: Repository not found` | the remote URL points at the wrong repo, possibly `-New` |
| `file exceeds GitHub's file size limit` | a large file was committed; name it, do not rewrite history |
| `push declined due to repository rule violations` | secret scanning has caught something — see section 5 |

If the cause is an expired credential, say so plainly. That is a five-minute fix for the human and an unfixable one for you.
