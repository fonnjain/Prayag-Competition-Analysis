## 1. What went wrong, so it is not repeated

P027r2 loaded 813 Prince prices from 11 worksheets. **The workbook has 13.** The two it never read are `PPR PIPE` and `PPR FITTINGS`, carrying **137 more Prince prices**.

The prompt caused this, not the loader. P027r2 supplied an eleven-row worksheet table and a fingerprint computed over eleven sheets, so the run had a target to conform to and conformed to it. Its own test — *"all 11 worksheets are read, none silently skipped"* — encoded the wrong number and therefore passed while 137 prices went unread.

```
byte hash received by the loader     20a3c363...ae5b89f     <- the 13-sheet workbook
fingerprint over 11 sheets           901d63a6...90658a17    813 rows   <- what was loaded
fingerprint over all 13 sheets       2b5b79da...02beb7ff    950 rows   <- what was in the file
```

Both fingerprints are real. The 813 that loaded are correct and stay. The 137 in PPR were never seen.

**The rule that follows:** a loader enumerates every worksheet the workbook actually contains and reports the list it found. It never takes the expected sheet list from the prompt. A count in a prompt is something to check *after* reading, never a filter applied while reading.

## 3. The effective date is per worksheet, not global

**This is the second thing P027r2 got wrong, and it would corrupt this load if carried over.**

P027r2 said *"the effective date is 2026-03-01, from the Prince column header."* That is true of the eleven sheets it read. It is **not** true of the two it did not:

```
CPVC ... UGD PIPE   Prince column header   2026-03-01
PPR PIPE            Prince column header   2026-08-18
PPR FITTINGS        Prince column header   2026-08-18
```

The PPR prices are five and a half months fresher. **Read the date from each worksheet's own Prince header and apply it to that worksheet's rows.** Do not take one date for the workbook. Do not fall back to the load date — that was batch 154, which wrote 1,828 rows dated the day they were loaded and overrode correct March prices.

Report the date you read for every worksheet.

## 7. Rules that do not bend

1. A competitor upload never creates a Prayag product.
2. **Do not read the Prayag price column.** Dated 10 August and known stale — its Casing Pipe values sit about 10% below the live catalogue.
3. Effective date from each worksheet's own header. See §3.
4. Preview, then Apply.
5. Provenance: byte hash, the 13-sheet fingerprint, row count, actor, `load_batch_id` on every row written.
6. No direct SQL against production.
7. Development first, then publish, then the same Preview → Apply in production.
