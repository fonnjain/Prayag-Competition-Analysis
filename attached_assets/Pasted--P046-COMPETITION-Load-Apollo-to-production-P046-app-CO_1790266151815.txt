# PART 1 — Before anything: development is not production

**This is the trap on this project, and it has caught us four times.**

P037 found production holds **231 products development does not** — the HDPE grid extension. Development's catalogue is 6,946. **Production's is not the same number.**

Apollo rows map to Prayag item codes. So:

**1.1** Report production's catalogue product count, with its clock time. Do not assume 6,946.

**1.2** In development, **5 Apollo rows had no matching Prayag code** and were excluded. **Check those 5 against production.** If production holds those products, Apollo would load **696** rows there, not 691.

**List all five with their Apollo code, their intended Prayag code, and whether production holds that product.** Report the expected production row count explicitly: 691, or 691 plus however many of the five match.

**A count that differs from development is not a failure. An unexplained count is.**

**1.3** Confirm production currently holds **0** Apollo price rows and **0** Apollo import batches, with the clock time.

---

# PART 2 — Gate the file on a content fingerprint, not a byte hash

An `.xlsx` is a zip. Re-saving it changes every byte while the values stay identical. A byte-hash gate stops a legitimate load; it has already done so once, under P027.

**2.1** Compute the content fingerprint over the values — the sorted normalised rows, joined, UTF-8, SHA-256 — and gate on that.

**2.2** **Enumerate the worksheets from the file, not from this prompt.** P027r2 read 11 sheets of a 13-sheet file because the brief listed 11, and 137 prices went missing. Report the sheet names you found and their count, from the file.

**2.3** Report the fingerprint and confirm it matches the file proven in development.
