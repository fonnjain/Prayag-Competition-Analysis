# P045 — Step 4 — COMPETITION — Fix the match key, then redo the cross-check

> **P045 Step 4** · app: **COMPETITION** (`prayag-price.com`)
> **Development only. Production is not loaded and not published.**
> Quote `P045 Step 4` when reporting back.

Step 3 settled three things and exposed one defect.

**Settled.** The workbook load is idempotent, proven across four runs with two reporting bugs found and fixed. The PDF detector now refuses rather than recommending an unsupported path. The 1,912 unverified rows cannot be resolved from database evidence — a hash identifies an import, not who originated each code — so that becomes a document review for people, not a code task.

**The defect.** The locally assigned match key is **already broken**:

```
272 locally assigned rows  ->  256 distinct keys
8 keys collide across 24 rows
all 272 contain heading-derived text
```

That is not a risk on the next file. Matching on that key is ambiguous for 24 products **today**, and one of them is the identity `APUGD007` is reserved against.

**A correction to the previous step's framing, which was mine.** I called the 418 agreeing PDF rows "real corroboration". Your check shows the agreement is **price only** — 0 of 418 agree on description and size, 22 on size alone, 174 PDF sizes blank. Same code, same price, nothing else established. It does not exclude a same-price row misalignment.

**These two are one problem.** Description comparison is useless precisely because workbook descriptions carry accumulated headings. Fix the key and the cross-check becomes possible.

# PART C — `PMN03122V` is loaded, disputed, and not marked as such

The workbook's **₹27** is loaded. The PDF — **the actual Apollo source document** — says **₹60**, against a different fitting.

Not removing it during a no-change load was correct. But the standing position is now the wrong way round: **the workbook is a derived artefact and the PDF is the source.** What is loaded is the derived value, and the source disagrees with it.

**C.1** Is the ₹27 row flagged as disputed anywhere a user would see it? If not, someone reading the app sees a price with no indication that the source document contradicts it. That is the failure this project keeps returning to — a record that looks settled and is not.

**C.2** Mark it as disputed. Do not change the value, do not apply ₹60, do not remove ₹27. **Flag it.**

**C.3** Report every other row where the PDF and the workbook disagree on price, whether or not it was approved. If there are more than the one, that changes the shape of Part B.
