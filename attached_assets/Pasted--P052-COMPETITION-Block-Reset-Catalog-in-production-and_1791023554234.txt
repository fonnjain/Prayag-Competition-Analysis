# P052 — COMPETITION — Block Reset Catalog in production, and make preview non-persisting

> **P052** · app: **COMPETITION** (`prayag-price.com`)
> **THIS PROMPT CHANGES CODE. It changes no stored product value.**
> Quote `P052` when reporting back.

The P051 Part 1 production audit found two things worth closing. Both were found by inspection, neither was invoked, and the data is confirmed unchanged (14,302 rows, matching checksum, byte-identical catalogue snapshot).

---

# PART 1 — Reset Catalog must be impossible in production

**This is the urgent half.** The audit at 15:54:52 IST found:

```
routes/catalog.ts        POST /catalog/reset — admin + spelling fingerprint, no production rejection
lib/catalogSeed.ts       loadCatalogSeed() — no production prohibition
src/index.ts             seedCatalogIfEmpty() can seed on startup
pages/data-health.tsx    the Reset Catalog screen action is still there
```

So **an admin can wipe and reseed the production catalogue from a screen**, and the only thing stopping it today is that the catalogue happens to be non-empty and the bundled seed happens to contain a duplicate key. Neither is a safety guard. 7,191 products and 14,302 price rows sit behind that button.

**1.1** `POST /catalog/reset` is **refused in production**, before any database work, with a clear message. The refusal is decided by the server from `current_database()` or the equivalent environment check — **not** by a request field, a header or anything the client can set.

**1.2** `loadCatalogSeed()` and `seedCatalogIfEmpty()` **refuse in production**, at the top of the function, before reading inputs. An empty production catalogue is an incident, not an invitation to reseed.

**1.3** The **Reset Catalog action is removed from the production screen**, not merely hidden by a flag the client evaluates. Report how `data-health.tsx` decides, and make the server the authority.

**1.4** Report every other endpoint or screen action that can delete, truncate, reseed or bulk-overwrite catalogue or price rows. **Enumerate from the code, not from this list.** For each, say whether it is now refused in production.

**1.5** Development keeps all of it. This prompt restricts production only.

---

# PART 2 — A preview that leaves nothing behind

The audit could not verify the live spelling preview, because a single-product preview **persists an approval-token record** and a bulk preview **persists a pending batch**. So the only way to see what a preview would show is to leave something behind.

**2.1** Add a **read-only spelling resolution check**: given a division and a typed category, it returns what would be written (matched existing spelling / new), every candidate with its active count, and nothing else. **It writes no row, no token, no batch, no log entry that needs clearing.** Admin only.

**2.2** Report, do not change, how long an unused approval token and an unused pending batch live, and whether anything clears them. If they accumulate, say how many are in each environment now.
