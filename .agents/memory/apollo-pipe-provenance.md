---
name: Apollo pipe provenance
description: Why Apollo local handles differ from workbook item identities, and why PDF pipe matches remain held
---

Apollo pipe references in the comparison workbook are locally assigned, not Apollo SKUs. Apollo's pipe PDF quotes product families, size and prices without pipe item codes; fittings do carry supplier codes. Unpriced pipe entries in the workbook represent coverage gaps, not unpriced supplier products. Check for numeric zero prices as well as blanks: the original source has CPVC rows with 0.00 that the initial blank-only tally missed.

**Why:** A generated pipe reference was previously mistaken for a supplier identity, and two pipe categories reused the same prefix. Treating that reference as a matching key could produce parallel duplicate rows on a later catalogue. The user explicitly confirmed that classifying numeric zero as a coverage gap, rather than a quoted price, was correct. A description-and-size key absorbed rolling worksheet headings and collided for 24 distinct mapped rows; some SWR rows do not repeat the diameter, so their row-owned Prayag item code is necessary to distinguish them.

**How to apply:** Preserve explicit origin on priced code rows. Use the stable sheet pipe classification, row-owned Prayag item code, and normalized row size for verified workbook pipe identity; the minted Apollo handle is not an authority. Supplier fittings match by supplier code. The Apollo PDF has no Prayag pipe item codes, so its pipe rows remain held rather than matched by the obsolete description key. Reconcile any future identity or reservation change before applying it; never infer origin for legacy records, invent a code for an unpriced row, or report a successful first/double load without an approved Apollo-to-Prayag mapping and an isolated end-to-end test. Keep supplier-code price conflicts separate from internal-code collision fixes.
